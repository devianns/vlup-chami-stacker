# Data-driven SSG RPG Engine · 별빛 골짜기

GitHub Pages에서 실행되는 데이터 기반 싱글 플레이 2D RPG 엔진입니다. Phaser 3, TypeScript, Vite로 구성되며 별도 서버가 필요 없습니다. 게임 시나리오는 엔진과 분리된 JSON으로 로드됩니다.

## 프로젝트의 목적

이 저장소의 핵심 결과물은 예제 게임 「별빛 골짜기」 자체가 아니라, **작가와 제작자가 자신의 이야기·세계관·게임 규칙·에셋을 주입해 독립적인 웹 RPG를 만드는 범용 엔진**입니다.

```text
재사용 가능한 RPG 엔진
        +
game.json (세계관, 스토리, 대사, 규칙, 밸런스)
        +
public/assets (캐릭터, 초상화, 몬스터, 맵, 음악)
        ↓
작품별로 완전히 다른 정적 웹 RPG
        ↓
GitHub Pages 배포 + 브라우저/파일 세이브
```

엔진은 이동·전투·대화·퀘스트·저장·렌더링처럼 모든 작품에 공통인 동작을 담당합니다. `game.json`은 작품 안에 무엇이 존재하고 어떤 조건에서 사건이 진행되는지 정의합니다. `public/assets`는 그 세계가 어떻게 보이고 들리는지를 결정합니다. 세이브에는 원본 시나리오가 아니라 플레이어의 진행 상태만 기록됩니다.

따라서 소설이나 직접 만든 이야기를 프로토콜에 맞춰 데이터화하고 이미지·음악을 함께 넣으면, 엔진 코드를 복사하거나 시나리오를 코드 안에 작성하지 않고도 중세 판타지, 현대 미스터리, SF, 무협, 공포, 교육용 역사 RPG 등 서로 다른 작품을 제작할 수 있습니다.

## 프로토콜 설계 원칙

- 콘텐츠와 실행 엔진은 분리합니다.
- 모든 데이터 연결은 표시 이름이 아닌 안정적인 ID를 사용합니다.
- 이미지 경로도 직접 반복하지 않고 에셋 매니페스트 ID로 참조합니다.
- 조건과 액션을 조합해 대화, 퀘스트, 오브젝트와 결말을 구성합니다.
- JSON Schema, 런타임 참조 검사와 미리보기 도구가 잘못된 설정을 배포 전에 찾습니다.
- `game.id`는 작품을, `game.version`은 같은 작품의 콘텐츠 업데이트를 식별합니다.
- 프로토콜 버전은 엔진이 해석할 수 있는 데이터 문법의 버전을 의미합니다.

## 실행

```bash
npm install
npm run dev
```

프로덕션 빌드는 `npm run build`, 테스트는 `npm test`로 실행합니다.
게임 데이터 참조만 빠르게 검사하려면 `npm run validate:content`를 실행합니다.

## 조작

- 이동: 방향키
- NPC 상호작용: E
- 공격: Space
- 퀵슬롯 사용: Q, W
- 저장: 3초마다 자동 저장, 수동 슬롯 3개, JSON 파일 내보내기/불러오기

## 현재 엔진 기능

- 별빛 마을, 햇살 들판, 안개 숲 사이의 출구 기반 맵 이동
- NPC 4명과 퀘스트 상태에 따라 달라지는 선택형 대화
- 성공 조건, 실패 조건, 목표 진행도를 표시하는 퀘스트 저널
- 지역별 몬스터 스폰 구역, 최대 개체 수, 리스폰 주기
- 플레이어, NPC, 몬스터, 출구를 실시간 표시하는 미니맵
- 구형 세이브를 현재 버전 3 진행 데이터로 자동 변환
- JSON 설정 기반 캐릭터 능력치, 성장 곡선, 전투 밸런스
- 아이템, 인벤토리, 소비 효과, 몬스터 드롭과 퀘스트 보상
- 조건과 액션을 조합하는 분기 대화 시스템
- 데이터 참조 무결성 검사와 설정 오류 화면
- 콘텐츠 업데이트 시 신규 퀘스트 병합과 삭제 데이터 정리
- 이미지·스프라이트시트·오디오 에셋 매니페스트
- 플레이어/NPC/몬스터 월드 이미지와 대화 초상화
- 맵 배경 이미지와 지역별 반복 배경 음악
- 장비 슬롯과 능력치 보정, 액티브 스킬, 버프·디버프
- 화폐와 NPC 상점 구매·판매
- 조건부 출구와 데이터 기반 상호작용 오브젝트
- 보스 체력 페이즈와 추적·돌진·범위 패턴
- 컷신 단계, 챕터 전환과 다중 엔딩 기록
- 스프라이트시트 애니메이션과 Tiled JSON 맵
- 모바일 터치 조작과 저장되는 음량 설정
- 브라우저 JSON 콘텐츠 검사·ID 미리보기
- 동서남북 좌표를 갖는 격자 월드와 전체 월드맵
- 경계 이동 시 반대편의 동일 축 위치를 유지하는 지역 전환
- 키보드 포커스와 툴팁을 지원하는 슬롯형 인벤토리
- 아이템·스킬을 지정할 수 있는 저장형 Q/W 퀵슬롯
- JSON 경로를 따라 왕복하는 NPC 순찰
- 절벽·폭포·고대 유적으로 이어지는 제1장 탐험 퀘스트라인

## 게임 콘텐츠 편집

게임 전체 설정은 [`public/game-data/game.json`](public/game-data/game.json)에 있습니다. 엔진 코드를 수정하지 않고 이 파일의 맵, NPC, 몬스터, 아이템, 퀘스트, 대사와 밸런스를 변경할 수 있습니다.

- 프로토콜: [`public/game-data/game.schema.json`](public/game-data/game.schema.json)
- 한국어 작성 가이드: [`docs/GAME_DATA_GUIDE.ko.md`](docs/GAME_DATA_GUIDE.ko.md)
- 런타임 검증기: [`src/game/ContentLoader.ts`](src/game/ContentLoader.ts)

`game.id`는 저장 공간의 식별자이므로 같은 게임 업데이트에서는 유지하고, 콘텐츠를 수정할 때 `game.version`을 올리는 것을 권장합니다.

### 맵 이미지와 충돌 데이터의 관계

고품질 배경 이미지는 시각 표현일 뿐이며 PNG/SVG의 집, 나무, 절벽 모양을 엔진이 자동으로 물리 충돌로 해석하지는 않습니다. 따라서 이 예제처럼 배경을 교체할 때는 `maps.*.objects`에 `solid: true`, `visible: false`인 충돌 영역을 이미지의 실제 지형에 맞춰 다시 작성해야 합니다. 문과 계단은 `exits`의 영역 및 `targetX`, `targetY`도 함께 조정합니다.

JSON만으로 사각형 충돌은 충분히 구성할 수 있지만 복잡한 다각형, 타일 단위 충돌, 높낮이와 이동 레이어까지 자동 추론할 수는 없습니다. 이 저장소를 포크해 전혀 다른 맵 에셋을 넣는 제작자는 다음 중 하나를 선택해야 합니다.

- 단순 맵: JSON 비가시 사각형 오브젝트를 배경에 맞춰 수동 배치
- 복잡한 맵: Tiled에서 충돌 레이어를 작성하고 `maps.*.tiled.collisionLayer`로 연결
- 특수 지형: 엔진 코드에 커스텀 충돌 도형이나 맵별 로직 추가

즉 시나리오·대사·퀘스트·스폰·일반 포탈은 데이터 주입만으로 교체할 수 있지만, 새 이미지의 시각적 지형과 물리 공간을 일치시키는 작업은 해당 에셋을 아는 제작자가 명시해야 합니다.

## GitHub Pages 배포

저장소 설정의 **Pages → Build and deployment → Source**를 **GitHub Actions**로 지정한 뒤 `main` 브랜치에 푸시하면 자동 배포됩니다. Vite의 상대 경로 설정 덕분에 프로젝트 페이지와 사용자 페이지 모두에서 동작합니다.
